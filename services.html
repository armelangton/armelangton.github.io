How projects are scoped

Custom implementation work is proposed as a defined project around the operational responsibility being delivered. The proposal sets the scope, systems, customer inputs, controls, acceptance criteria, handoff, and stabilization boundary. Palomma does not publish generic dollar starting points because those details can materially change the work required.

  • A separate scoping engagement is used only when material uncertainty prevents a responsible implementation proposal.
  • A prototype or proof is used only when a specific feasibility question needs to be answered before production work.
  • Ongoing enhancements, maintenance, or optimization are optional and scoped separately when useful; a mandatory retainer is not required.
